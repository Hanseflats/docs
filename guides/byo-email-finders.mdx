title: "BYO email & phone finders"

Bring your own (BYO) provider keys so scraper `find_email` / `find_phone` runs **synchronously** and charges **0 Lens email/phone credits**. The provider bills your account instead.

You can use a single provider or an **ordered waterfall** — we try each provider in sequence until email and/or phone is found.

## Providers

| Provider | Email | Phone | Typical input |
| --- | --- | --- | --- |
| `findymail` | Yes | No | Name + employer domain |
| `leadmagic` | Yes | No | Person LinkedIn URL |
| `prospeo` | Yes | Yes | LinkedIn **or** name + company/domain |
| `ai_ark` | Yes | Yes | LinkedIn (email); LinkedIn or domain+name (phone) |
| `blitzapi` | Yes | Yes (US) | Person LinkedIn URL |

## Save keys + default order

```bash
curl -X PUT https://app.lens.ly/api/v1/integrations/email-finders \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "prospeo_api_key": "…",
    "ai_ark_api_key": "…",
    "blitzapi_api_key": "…",
    "byok_provider_order": ["prospeo", "ai_ark", "blitzapi"]
  }'
```

Accepted body fields (any subset):

- `findymail_api_key`, `leadmagic_api_key`, `prospeo_api_key`, `ai_ark_api_key`, `blitzapi_api_key`
- `byok_provider_order` — ordered unique list (max 5). Pass `[]` to clear.

`GET` returns masked keys plus `byok_provider_order`. `DELETE ?provider=…|all` clears keys (`all` also clears the order).

Dashboard: **Integrations → Contact finders (BYO)** — add keys and reorder the default waterfall.

## Waterfall on a scraper

**Per-request override** (preferred for API callers):

```bash
curl -X POST https://app.lens.ly/api/v1/scrapers/linkedin-profile \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://www.linkedin.com/in/example",
    "find_email": true,
    "find_phone": true,
    "email_providers": ["prospeo", "ai_ark", "blitzapi"]
  }'
```

**Single-provider shorthand** (still supported):

```json
{ "find_email": true, "email_provider": "prospeo" }
```

**Saved default:** omit both fields — if `byok_provider_order` is set and keys exist, sync uses that order. If there is no order/keys, `find_email` runs the async Lens/RevenueBase path (charged).

### How resolution works

1. Request `email_providers` (if set)
2. Else request `email_provider`
3. Else saved `byok_provider_order` (providers without a saved key are skipped)
4. Else empty → async RB email (when `find_email`)

Per record we walk the list: stop email attempts after the first hit; stop phone after the first hit. Phone skips Findymail/LeadMagic. Winning sources are tagged `byo_<provider>`.

### Notes

- `email_api_key` in the body is only allowed with a **single** provider (not multi-provider waterfalls). Save keys for waterfalls.
- `find_phone` needs at least one phone-capable provider (`prospeo` / `ai_ark` / `blitzapi`) with a key in the resolved list.
- Async jobs cannot accept `email_api_key` in the body.
