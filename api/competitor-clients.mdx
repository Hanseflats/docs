Launch via the [Audiences API](/api/audiences) with `play_slug: "competitor-clients"`.

Enter a competitor domain (e.g. `hubspot.com`). We return **client companies** of that competitor.

This play is **one-shot** (not recurring) and returns companies only.

## Endpoint

```bash
POST https://app.lens.ly/api/v1/audiences
```

## Params

| Parameter | Required | Description |
| --- | --- | --- |
| `competitor_domain` | Yes | Competitor website/domain to find clients of. Example: `hubspot.com` |
| `max_clients` | No | Cap on unique client companies (defaults to `number_of_leads`). Example: `100` |

Also pass top-level audience fields:

| Parameter | Required | Description |
| --- | --- | --- |
| `play_slug` | Yes | Must be `competitor-clients` |
| `number_of_leads` | No | Target company count (default `100`) |
| `title` | No | Display name |
| `delivery_webhook_url` | No | Webhook for delivery |

Inspect the live schema anytime:

```bash
curl https://app.lens.ly/api/v1/audiences/plays/competitor-clients \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Example request

```bash
curl -X POST https://app.lens.ly/api/v1/audiences \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: competitor-clients-1" \
  -d '{
  "play_slug": "competitor-clients",
  "source_params": {
    "competitor_domain": "hubspot.com",
    "max_clients": 100
  },
  "number_of_leads": 100,
  "title": "HubSpot clients"
}'
```

## Response

```json
{
  "audience": {
    "id": "a1b2c3d4-...",
    "title": "HubSpot clients",
    "play_slug": "competitor-clients",
    "status": "pending"
  },
  "status": "triggered",
  "stream_url": "/api/v1/audiences/a1b2c3d4-.../stream"
}
```

Poll with `GET /api/v1/audiences/{id}`. Export with `GET /api/v1/audiences/{id}/export?type=companies`.

## Streaming results (SSE)

Create still returns immediately. To show companies as they are found, open the stream URL from the launch response:

```bash
GET /api/v1/audiences/{id}/stream
```

Same auth as other v1 routes (`Authorization: Bearer` / `x-api-key`). Prefer `fetch` \+ `ReadableStream` — browser `EventSource` cannot send auth headers.

Events:

| Event | Payload |
| --- | --- |
| `company` | `{ company: { id, name, domain, url, ... } }` |
| `status` | `{ status, companies_total, leads_total }` |
| `done` | `{ status, companies_total, leads_total }` |
| `error` | `{ error }` |

Optional query: `?after=<ISO timestamp>` to resume after a cursor.

```js
const res = await fetch(`https://app.lens.ly/api/v1/audiences/${id}/stream`, {
  headers: { Authorization: `Bearer ${API_KEY}` },
});
const reader = res.body.getReader();
const decoder = new TextDecoder();
let buf = '';
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buf += decoder.decode(value, { stream: true });
  const parts = buf.split('\n\n');
  buf = parts.pop() || '';
  for (const chunk of parts) {
    const event = /event: (\w+)/.exec(chunk)?.[1];
    const dataLine = chunk.split('\n').find((l) => l.startsWith('data: '));
    if (!event || !dataLine) continue;
    const data = JSON.parse(dataLine.slice(6));
    if (event === 'company') console.log(data.company);
    if (event === 'done') break;
  }
}
```

Companies stream in as the run progresses; the stream closes when the audience completes.

## Notes

- `competitor_domain` is required.
- Companies are deduped by domain; the competitor domain itself is excluded.
- One-shot only — do not pass `cadence`.
- Billing mode: company (1 / company).
